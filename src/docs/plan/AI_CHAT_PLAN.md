## 1. 목적

### 왜 채팅인가?

| 현재 | 채팅 도입 후 |
|------|-------------|
| 콘텐츠 선택 → 사주 입력 → AI 생성 → 결과 1회 열람 | 자유 대화로 즉시 운세 상담 |
| 결과 수동적 소비 | 후속 질문, 심화 해석 가능 |
| 재방문 동기 약함 | "오늘 운세 물어볼까?" → 일상 루틴화 |
| 무료 콘텐츠 → 유료 전환만 존재 | 무료 채팅 → 유료 채팅 / 유료 콘텐츠 이중 전환 |

### 기대 효과

- **재방문율 향상**: 매일 대화할 이유 생김 (사주GPT 핵심 리텐션 요인)
- **무료 → 유료 전환 퍼널 추가**: 무료 채팅 → 더 정확한 분석 원할 때 유료 전환
- **이탈률 감소**: 콘텐츠 선택 고민 없이 바로 대화 시작
- **나다움 태그 자연 수집**: 대화 중 성향 파악 → 태그 자동 추출

## 2. 경쟁사 분석 (사주GPT)

### 모델 구조

| 등급 | 모델 | 비용 구조 |
|------|------|----------|
| 무료 (하루 10턴) | Qwen3-30B-A3B (자체 파인튜닝) | 자체 GPU 서버 |
| 플러스 | 위 + GLM-4.5 대체 | 자체 서버 |
| PRO | Claude Sonnet 4.6 | API 과금 |
| 플레어 | GPT-5 | API 과금 |
| VIP | Claude Opus 4.6 | API 과금 |

### 사주GPT의 핵심 경쟁력

1. **2년간 60회+ 파인튜닝**한 자체 사주 특화 모델
2. **자체 서버 3대** 운영 → 무료 트래픽 API 비용 0원
3. **Tool Agent (GLM-4.5)** + MCP 서버 → 만세력/별자리 데이터 실시간 연동
4. **포인트 시스템**: 일일 100P 출석 + 충전 → 수익 모델

### 사주GPT 약점 (나다운세 차별화 기회)

- UI/UX가 전형적인 ChatGPT 클론 (대화만 가능)
- 시각적 요소 없음 (타로 카드 이미지, 인포그래픽 등)
- 나다움 태그 같은 개인화 시스템 없음
- 주간 보고서 같은 푸시형 콘텐츠 없음

## 3. 모델 선정

### 속도 + 비용 + 품질 종합 비교

| 모델 | 출력 속도 | TTFB | 비용 (1M tok) | 한국어 | 종합 |
|------|----------|------|--------------|--------|------|
| **Gemini 2.5 Flash** | ~350 tok/s | ~0.3초 | $0.15 / $0.6 | 상 | **1순위** |
| GPT-4.1-mini | ~150 tok/s | ~0.5초 | $0.4 / $1.6 | 상 | 2순위 |
| GPT-4.1-nano | ~200 tok/s | ~0.4초 | $0.1 / $0.4 | 중상 | 3순위 (품질↓) |
| DeepSeek V3 | ~60-100 tok/s | ~1초+ | $0.27 / $1.1 | 중상 | 피크시 느림 |
| Claude Haiku 4.5 | ~100 tok/s | ~0.8초 | $0.8 / $4 | 상 | 비쌈 |

### 결정: Gemini 2.5 Flash (1순위)

**선정 이유**:
- 채팅 체감 속도 압도적 (350 tok/s, TTFB 0.3초)
- 한국어 토큰 효율이 영어 대비 ~2배 소모 → 속도가 더 중요
- 가격 최저 수준 (GPT-4.1-mini 대비 ~60% 저렴)
- 한국어 사주/운세 도메인 품질 충분
- 이미 나다운세에서 이미지 생성용으로 사용 중 (인프라 친숙)

**대안 (Fallback)**: GPT-4.1-mini (Gemini 장애 시)

## 4. 비용 시뮬레이션

### 가정

- 턴당 평균: 입력 300 토큰 + 시스템 프롬프트 500 토큰 + 출력 500 토큰
- 한국어 보정: x1.8 (토큰 효율)
- 컨텍스트 누적: 평균 5턴 대화 시 입력 점진 증가

### Gemini 2.5 Flash 기준

| 시나리오 | DAU | 턴/일/유저 | 월 턴 수 | 월 비용 (예상) |
|----------|-----|-----------|---------|---------------|
| 초기 | 50 | 5 | 7,500 | **~3,000원** |
| 성장 | 300 | 8 | 72,000 | **~30,000원** |
| 안정 | 1,000 | 10 | 300,000 | **~12만원** |
| 고트래픽 | 5,000 | 10 | 1,500,000 | **~60만원** |

> 사주GPT 방식(자체 GPU 서버)은 월 50~150만원 고정비 → DAU 5,000 이상에서만 API보다 유리

## 5. 구현 아키텍처

### Phase 1 아키텍처

```
┌─────────────────────────────────────────────────────────┐
│                     CLIENT                               │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  [ChatPage.tsx]                                          │
│      ├── ChatMessageList (메시지 목록, 스트리밍)          │
│      ├── ChatInput (입력창, 턴 제한 표시)                │
│      └── ChatSuggestions (추천 질문 칩)                   │
│                                                          │
│  스트리밍: SSE (Server-Sent Events)                      │
│                                                          │
└──────────────────────┬──────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│               EDGE FUNCTION (chat-stream)                │
├─────────────────────────────────────────────────────────┤
│                                                          │
│  1. 인증 체크 (로그인 여부)                               │
│  2. 턴 제한 체크 (비회원 3턴, 회원 무료 10턴/일)          │
│  3. 사주 정보 조회 (saju_records)                        │
│  4. 나다움 태그 조회 (user_trait_tags) → 개인화           │
│  5. 시스템 프롬프트 구성                                  │
│  6. Gemini 2.5 Flash API 호출 (스트리밍)                 │
│  7. SSE로 클라이언트에 스트리밍 전달                      │
│  8. 대화 로그 저장 (chat_sessions, chat_messages)         │
│                                                          │
└─────────────────────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────┐
│                    GEMINI API                             │
│             (스트리밍 응답, SSE)                          │
└─────────────────────────────────────────────────────────┘
```

### DB 스키마 (신규 테이블)

```sql
-- 채팅 세션
CREATE TABLE chat_sessions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES auth.users(id),
    -- 비회원은 fingerprint로 식별
    anonymous_fingerprint TEXT,
    title TEXT,                          -- 첫 질문 기반 자동 생성
    saju_record_id UUID REFERENCES saju_records(id),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- 채팅 메시지
CREATE TABLE chat_messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    session_id UUID REFERENCES chat_sessions(id) ON DELETE CASCADE,
    role TEXT NOT NULL CHECK (role IN ('user', 'assistant', 'system')),
    content TEXT NOT NULL,
    tokens_used INTEGER,                -- 비용 추적
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 일일 턴 사용량 추적
CREATE TABLE chat_daily_usage (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID REFERENCES auth.users(id),
    anonymous_fingerprint TEXT,
    date DATE DEFAULT CURRENT_DATE,
    turns_used INTEGER DEFAULT 0,
    UNIQUE(user_id, date),
    UNIQUE(anonymous_fingerprint, date)
);
```

### 시스템 프롬프트 전략

```
[기본 역할]
당신은 나다운세의 AI 운세 상담사입니다.
사주명리학과 타로에 정통한 전문가로서 따뜻하고 친근하게 상담합니다.

[사주 정보] (DB에서 자동 주입)
상담자: {nickname}, {birthdate}, {gender}, {lunar/solar}
사주 원국: {천간/지지 정보} (있으면)

[나다움 태그] (개인화 핵심 - 차별화 포인트)
상담자 성향 키워드: {confirmed_tags}
→ 이 키워드를 참고하여 상담자의 성향에 맞는 맞춤 해석을 제공하세요.

[제약]
- 한 답변은 300자 이내로 간결하게
- 의학/법률/재정 조언은 전문가 상담 권유
- 지나치게 부정적인 예언 금지
```

## 6. 무료/유료 설계

### 턴 제한 모델

| 구분 | 일일 무료 턴 | 모델 | 기능 |
|------|------------|------|------|
| **비회원** | 3턴 | Gemini 2.5 Flash | 기본 상담 |
| **회원 (무료)** | 10턴 | Gemini 2.5 Flash | 기본 상담 + 사주 연동 |
| **유료 (향후)** | 무제한 | GPT-5 / Claude | 심화 상담 + 대화 저장 |

### 전환 유도 포인트

```
무료 3턴 소진
    ↓
"더 깊은 상담을 원하시면 로그인하세요" → 회원가입 유도
    ↓
무료 10턴 소진
    ↓
"오늘의 무료 상담이 끝났어요.
 내일 다시 만나요! 🔮
 지금 바로 심화 해석을 원하시면?" → 유료 콘텐츠 연결
```

## 7. 나다운세 차별화 요소

사주GPT와의 차별점:

| 요소 | 사주GPT | 나다운세 채팅 |
|------|---------|-------------|
| 개인화 | 사주 정보만 | 사주 + **나다움 태그** (성향 키워드) |
| 시각 요소 | 텍스트만 | 타로 카드 이미지, 인포그래픽 |
| 연계 콘텐츠 | 없음 | 채팅 → 유료 심화 해석판 자연 연결 |
| 푸시 콘텐츠 | 없음 | 주간 보고서 + 알림톡 |
| UI/UX | ChatGPT 클론 | 모바일 최적화 운세 특화 UI |

## 8. 로드맵

### Phase 1: MVP (2~3주)

- [ ] `chat-stream` Edge Function (Gemini 2.5 Flash, SSE 스트리밍)
- [ ] `ChatPage.tsx` 기본 UI (메시지 리스트 + 입력창)
- [ ] 비회원 3턴 / 회원 10턴 일일 제한
- [ ] 사주 정보 자동 연동 (시스템 프롬프트 주입)
- [ ] DB 스키마 (chat_sessions, chat_messages, chat_daily_usage)

### Phase 2: 개인화 (2주)

- [ ] 나다움 태그 시스템 프롬프트 연동
- [ ] 대화 히스토리 저장/불러오기
- [ ] 추천 질문 (오늘의 운세, 이번 주 연애운 등)
- [ ] 채팅 → 유료 콘텐츠 전환 유도 UI

### Phase 3: 고도화 (선택)

- [ ] 파인튜닝 (OpenAI GPT-4o-mini, 채팅 로그 기반 학습 데이터 구축)
- [ ] 유료 채팅 등급 (GPT-5 / Claude Sonnet)
- [ ] 타로 카드 이미지 인라인 표시
- [ ] 음성 입력 (STT) 지원

## 9. 리스크 & 대응

| 리스크 | 영향 | 대응 |
|--------|------|------|
| Gemini API 장애 | 채팅 불가 | GPT-4.1-mini Fallback 구현 |
| 비용 폭증 (바이럴) | 예산 초과 | 일일 전체 턴 캡 설정 (예: 10,000턴/일) |
| 부적절한 답변 | 서비스 신뢰도 하락 | 시스템 프롬프트 제약 + 후처리 필터 |
| Edge Function 150초 타임아웃 | 긴 대화 끊김 | 스트리밍이라 문제 없음 (토큰 단위 전송) |
| 사주 정보 없는 사용자 | 개인화 불가 | 대화 중 생년월일 자연스럽게 수집 |
