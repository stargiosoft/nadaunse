# 유료 콘텐츠 사주 API 효율화 전략 (v3)

> **목적**: 유료 콘텐츠(심화 해석판)의 사주 API 데이터를 질문 유형별로 선별 전달하여 AI 해석 품질 향상 + 토큰 절감
> **상태**: ✅ **구현 완료** (2026-03-17 스테이징 배포)
> **적용 대상**: `generate-saju-answer`, `generate-content-answers`, `server/sajuKnowledgeMap.ts`
> **최종 업데이트**: 2026-03-17 (v3: 구현 완료 후 실측 데이터 반영)

---

## 1. 현재 방식과 문제점

### 이전 플로우 (개선 전)

```
Stargio API 호출 → JSON 전체 (~42키) → cachedSajuData에 저장
  → 모든 사주 질문에 동일한 전체 JSON 전달
  → generate-saju-answer 프롬프트에 JSON.stringify 덤프
```

### 개선된 플로우 (현재)

```
Stargio API 호출 → JSON 전체 (~42키) → cachedSajuData에 저장
  → generate-content-answers가 categoryMain을 generate-saju-answer에 전달
  → buildOptimizedSajuPrompt(sajuData, categoryMain, questionText) 호출
  → 질문 유형별 핵심 필드 선별 + 오행/십성 관계 맥락 주입 → AI
```

### 이전 방식의 문제점 (해결 완료)

| 문제 | 상세 | 영향 | 해결 |
|------|------|------|------|
| **토큰 낭비** | 12신살, 기타신살, 본사주 등 거의 안 쓰는 필드도 매번 전송 | 비용 증가 | ✅ 카테고리별 선별 (~83% 절감) |
| **AI 집중도 저하** | 데이터가 많으면 AI가 핵심에 덜 집중 | 해석 품질 저하 | ✅ 핵심 필드만 전달 |
| **관계 맥락 부재** | 편관↔비견 상호작용 맥락 없음 | AI가 알아서 추론 | ✅ 오행/십성 맥락 주입 |
| **질문 유형별 차별화 없음** | 동일 데이터 덤프 | 불필요 정보 과다 | ✅ 12개 카테고리별 필드 매핑 |

### 코드 위치

| 파일 | 역할 |
|------|------|
| `server/sajuKnowledgeMap.ts` | 질문 분류 + 필드 선별 + 맥락 생성 (핵심 모듈) |
| `generate-saju-answer/index.ts` | `buildOptimizedSajuPrompt()` 호출하여 최적화된 프롬프트 생성 |
| `generate-content-answers/index.ts` | `content.category_main`을 generate-saju-answer에 전달 |

## 2. 개선 전략: 질문 유형별 선별 전달

### 핵심 아이디어

```
이전:  전체 사주 JSON → AI (약 7,000자)
현재:  질문 유형 분류 → 핵심 필드만 추출 → 관계 맥락 주입 → AI (약 1,200자, ~83% 절감)
```

### 2-1. 사주 API 응답 필드 중요도 분류

#### 항상 포함 (공통 핵심)

| 필드 | 설명 | 이유 |
|------|------|------|
| `사주` | 4주 천간지지 ["戊申", "壬戌", "甲寅", "癸未"] | 모든 해석의 기본 |
| `오행` | 4주 오행 ["土金", "水土", "木木", "水土"] | 오행 균형 분석 |
| `십성` | 4주 십성 배열 | 성격/운세 핵심 |
| `발달오행` | {木:41, 火:0, 土:40, 金:15, 水:4} | 오행 강약 수치 |
| `발달십성` | {식상:41, 재성:0, 관성:40, 비겁:4, 인성:15} (5그룹) | 십성 강약 수치 (그룹 레벨) |
| `격구분` | "제살태과격" 등 | 사주 성격 핵심 |
| `용신` | {용신, 희신, 기신} | 보완 방향 핵심 |
| `용신오행` | {용신:["금"], 희신:["수"], 기신:["토","목","화"]} | 용신의 오행 매핑 (용신과 반드시 쌍으로) |
| `사주강약` | "신강" / "신약" | 기본 체질 |
| `물상론` | {닉네임, 성격, 인간관계} | 비유적 해석 |
| `성별` | 남/여 | 기본 정보 |

#### 항상 제외

| 필드 | 제외 이유 |
|------|----------|
| `대운순서` | 12개 대운 타임라인, 직접 활용도 낮음 |
| `대운시작나이` | 나이 언급 금지 가이드와 충돌 |
| `대운순서십이운성` | 토큰 대비 활용도 낮음 |
| `대운순서십성` | 토큰 대비 활용도 낮음 |
| `용신설명` | 매우 길고 용신+용신오행 필드로 대체 가능 |

#### ⚠️ 선별 포함 (v1에서 "항상 제외"였던 필드)

| 필드 | 변경 | 이유 |
|------|------|------|
| `본사주` | 전체 제외 → **핵심 이벤트만 선별 포함** (`충`, `원진`, `형`, `천을귀인`) | 충/원진은 갈등/관계 해석에 중요, 천을귀인은 귀인 판단에 필수. `백호살`, `괴강살` 등 나머지 신살은 제외 |
| `세운[year].월별간지/월별십성` | ~~월운보기 항상 제외~~ → **월별/시기 질문 시 조건부 포함** | 실제 API에 `월운보기` 키는 없음. 월별 데이터는 `세운[year].월별간지`, `세운[year].월별십성`에 존재. "이번 달", "몇 월에" 등 시기 특정 질문에만 해당 월 데이터 포함 |

### 3-4. 십성 상호작용 맥락

> **v1 기준**: `발달십성`은 5그룹 레벨(`식상`, `재성`, `관성`, `비겁`, `인성`)로 제공됨.
> 아래 상호작용 매핑은 **개별 십성(10개)** 기준이므로, 그룹→개별 변환이 필요:
> - 비겁 = 비견 + 겁재 | 식상 = 식신 + 상관 | 재성 = 정재 + 편재
> - 관성 = 정관 + 편관 | 인성 = 정인 + 편인
>
> **v1 구현**: `십성` 배열(4주 각 천간지지의 개별 십성)에서 가장 빈도 높은 2개를 추출하여 매핑.
> 또는 `발달십성` 상위 2그룹으로 단순 매핑 (예: 식상 1위 + 관성 2위 → `식신+정관` 또는 `상관+편관`).

## 6. 구현 상세 (완료)

### 핵심 모듈: `server/sajuKnowledgeMap.ts`

```
위치: supabase/functions/server/sajuKnowledgeMap.ts
export 함수:
  - classifyQuestionType(categoryMain, questionText) → CategoryMain
  - buildOptimizedSajuPrompt(sajuData, categoryMain, questionText) → string
```

**classifyQuestionType 로직:**
1. `categoryMain`이 12개 유효 카테고리 중 하나면 그대로 사용
2. `'기타'`이거나 누락이면 `questionText` 키워드 매칭 (빈도 기반)
3. 매칭 실패 시 `'개인운세'` 폴백

**buildOptimizedSajuPrompt 로직:**
1. 공통 핵심 필드 추출 (사주, 오행, 십성, 발달오행, 발달십성, 격구분, 용신+용신오행, 사주강약, 물상론, 성별)
2. 카테고리별 추가 필드 추출 (`CATEGORY_FIELD_MAP` ●/○/- 매핑)
   - 세운: `sajuData.세운[String(new Date().getFullYear())]` 동적 연도 키
   - 본사주: 충, 원진, 형, 천을귀인만 선별 (빈 문자열이면 자동 제외)
   - 월별 질문 감지: "3월", "이번 달" 등 → 해당 월 간지/십성 포함
3. 오행 상생/상극 관계 맥락 자동 생성 (발달오행 수치 기반, 상위 2 vs 하위 2)
4. 카테고리별 핵심 십성 해석 텍스트 생성
5. 발달십성 상위 2그룹 → 십성 배열에서 개별 십성 빈도 확인 → 상호작용 맥락 주입
6. 구조화된 마크다운 텍스트로 조립

### generate-saju-answer 변경점

```
- import { buildOptimizedSajuPrompt } from '../server/sajuKnowledgeMap.ts' 추가
- 파라미터에 categoryMain 추가 수신
- 이전: ${JSON.stringify(sajuData, null, 2)} + 정적 십성 참조표
- 현재: ${buildOptimizedSajuPrompt(sajuData, categoryMain, questionText)}
```

### generate-content-answers 변경점

```
- generate-saju-answer 호출 시 body에 categoryMain: content.category_main 추가
```

```typescript
  간지: string;          // "丙午"
  총평: string;          // 종합 해석 텍스트
  충: string;            // 충 관계 ("인오충" 등, 빈 문자열이면 없음)
  원진: string;          // 원진 관계
  천을귀인: string;      // 귀인 여부
  '12신살': string;      // 해당 연도 12신살
  월별간지: Record<string, string>;    // {"1": "丁丑", "2": "戊寅", ...}
  월별십성: Record<string, string[]>;  // {"1": ["정재","정관"], "2": ["편재","편관"], ...}
  운세점수: {
    직장운: number;      // 0-100
    재물운: number;
    대인관계운: number;
    연애운: number;
  };
}
```

### 용신 + 용신오행 — 반드시 쌍으로 포함

```typescript
// ❌ 용신만 포함
sajuData.용신   // {용신: "...", 희신: "...", 기신: "..."}

// ✅ 용신 + 용신오행 쌍으로 포함
sajuData.용신       // {용신: "...", 희신: "...", 기신: "..."}
sajuData.용신오행   // {용신: ["금"], 희신: ["수"], 기신: ["토", "목", "화"]}
// 용신오행이 있어야 AI가 오행 관계(상생/상극)를 정확히 분석 가능
```

### 발달십성 — 5그룹 레벨

```typescript
// 실제 구조: 10개 개별 십성이 아닌 5그룹
sajuData.발달십성   // {식상: 41, 재성: 0, 관성: 40, 비겁: 4, 인성: 15}

// 개별 십성 정보가 필요하면 `십성` 배열 참조
sajuData.십성       // [["편관","편인"], ["비견","편인"], ["편관","비견"], ["겁재","정관"]]
```

### 오주 계열 — `오행분석` 키 없음

```typescript
// ❌ 존재하지 않는 키: sajuData.오행분석
// ✅ 실제 키:
sajuData.오주        // 5주 천간지지
sajuData.오주오행    // 5주 오행
sajuData.오주십성    // 5주 십성
```

### 존재하지 않는 키 주의

```typescript
// ❌ 존재하지 않음:
sajuData.오늘           // 없음 — 오늘의운세, 오늘의직장운 등 별도 키로 존재
sajuData.월운보기       // 없음 — 월별 데이터는 세운[year].월별간지/월별십성에 존재
sajuData.세운.올해      // 없음 — 세운["2026"] 형태로 접근
sajuData.세운.내년      // 없음 — 세운["2027"] 형태로 접근
```
