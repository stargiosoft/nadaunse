**order_results 테이블 실태**:

| 주문 | 콘텐츠 | 예상 질문 | 생성된 행 | 누락 질문 | gpt_response | status |
|------|--------|----------|----------|----------|-------------|--------|
| `3ebe62b2` | MBTI 사주심리학 | 10개 (q1~10) | **8개** (q3~10) | **q1, q2** | ✅ 모두 있음 (1029~1353자) | 전부 pending |
| `4b4f1593` | 황금기는 언제 | 10개 (q1~10) | **4개** (q3,6,9,10) | **q1,2,4,5,7,8** | ✅ 모두 있음 (872~1209자) | 전부 pending |

**핵심 발견**:
- `order_results.status = "pending"`은 **정상 상태**임 (성공한 재구매 건도 전부 pending)
- 프론트엔드는 `orders.ai_generation_completed` 플래그로 완료 판단
- 실패 원인: **일부 질문 행(row)이 아예 생성되지 않음** + `ai_generation_completed`가 false로 남음
- 생성된 질문들의 AI 응답은 정상 (1000자 내외, 적절한 길이)

### 확정 원인

**self-continue 체인 중 일부 질문 생성 누락**

`generate-content-answers` 오케스트레이터가 배치 병렬 생성 중:
1. 일부 질문의 `order_results` 행 INSERT 자체가 실패 (row가 존재하지 않음)
2. 나머지 질문은 응답까지 정상 생성됨
3. 모든 질문이 완료되지 않아 `ai_generation_completed = true` 전환 실패
4. → 프론트엔드에서 영원히 "로딩중" 표시

**가능성**:
- Supabase Edge Function 동시 DB 쓰기 경합 (race condition)
- 또는 self-continue 재호출 시 이미 생성된 질문 목록 계산 오류로 일부 질문 스킵

## 5. CS 처리 방안

### 방안 A: 데이터 복구 + 부분 환불 (권장)

**Order 1 (`3ebe62b2` — MBTI 사주심리학)**: 복구 가능
- 누락 2개(q1,q2)만 재생성하면 10/10 완성
- `generate-content-answers` Edge Function 재호출 or 수동 INSERT + AI 생성
- 완료 후 `ai_generation_completed = true` 설정
- → 환불 불필요 (고객이 정상 콘텐츠 열람 가능)

**Order 2 (`4b4f1593` — 황금기)**: 환불 처리
- 누락 6개(q1,2,4,5,7,8) — 복구 비용 높음
- 고객이 이미 재구매(`8811e4ea`)로 정상 결과 수령
- → **30새싹 환불** (중복 결제 보상)

### 방안 B: 전액 환불 (간편)

- 실패 2건 × 30새싹 = **60새싹 환불**
- 현재 잔액 10새싹 → 환불 후 70새싹
- Order 1의 부분 생성 데이터는 그대로 둠 (열람 불가 상태 유지)

### 고객 특성

```

  maxExecutionMs: 100_000,   // 100초 (150초 제한 - 50초 버퍼)
```
