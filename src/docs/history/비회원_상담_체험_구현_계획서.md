# 비회원 상담 체험 1회 제한 구현 계획서

> **작성일**: 2026-03-04
> **목적**: 홈 화면 사주 상담 / 타로 상담을 비로그인 유저에게 합쳐서 1회 체험 제공
> **다음 세션에서 이 문서를 기반으로 구현 진행**

---

## Context

홈 화면의 사주 상담 / 타로 상담 기능을 비로그인 유저에게도 **합쳐서 1회** 체험 기회를 제공한다.
2회째 시도부터는 LoginBottomSheet을 표시하여 로그인을 유도한다.
기존 `anonymous_free_views` 테이블의 일일 제한(3/일) 패턴을 참고하되, 상담은 **영구 제한**(fingerprint당 1회)이므로 별도 테이블을 사용한다.

## 1. DB: `anonymous_consult_views` 테이블 생성

**별도 테이블 추천 이유**: anonymous_free_views는 일일 제한 + pg_cron 매일 삭제. 상담은 영구 제한이라 retention 정책이 다름.

```sql
CREATE TABLE IF NOT EXISTS public.anonymous_consult_views (
    id uuid DEFAULT gen_random_uuid() PRIMARY KEY,
    fingerprint text NOT NULL,         -- sha256(IP + User-Agent)
    consult_type text NOT NULL,        -- 'saju' | 'taro' (기록용)
    created_at timestamptz DEFAULT now()
);

-- fingerprint + consult_type 중복 방지
CREATE UNIQUE INDEX idx_anon_consult_fp_type
    ON public.anonymous_consult_views (fingerprint, consult_type);

-- fingerprint 조회용 인덱스
CREATE INDEX idx_anon_consult_fp
    ON public.anonymous_consult_views (fingerprint);

-- RLS Enabled (정책 없음 → Service Role Key 전용)
ALTER TABLE public.anonymous_consult_views ENABLE ROW LEVEL SECURITY;
```

**제한 체크 쿼리**: `SELECT COUNT(*) FROM anonymous_consult_views WHERE fingerprint = ?` → count >= 1이면 차단 (사주+타로 합산)

**파일**: `supabase/migrations/YYYYMMDD_create_anonymous_consult_views.sql`

## 6. Edge Function 변경

### 6-A. `supabase/functions/generate-saju-consult/index.ts`

**변경 포인트:**

1. **입력 검증 분기:**
```typescript
const { question, sajuRecordId, userId, birthInfo } = requestBody;

// Path A: 로그인 유저 (기존) — sajuRecordId && userId 존재
// Path B: 비로그인 유저 (신규) — birthInfo 존재
```

2. **비로그인 Path B 로직:**
```typescript
// fingerprint 생성 (generate-free-preview와 동일 패턴)
const ip = req.headers.get('x-forwarded-for')?.split(',')[0]?.trim() || ...
const fingerprint = sha256(ip + userAgent)

// 제한 체크: fingerprint에 ANY 기록 있으면 차단 (합산 1회)
const { count } = await supabase
  .from('anonymous_consult_views')
  .select('*', { count: 'exact', head: true })
  .eq('fingerprint', fingerprint)

if (count && count >= 1) {
  return Response({ success: false, error: 'CONSULT_LIMIT_REACHED' })
}

// birthInfo에서 questionerInfo 구성
const questionerInfo = `이름: ${birthInfo.name}, 성별: ${birthInfo.gender}, ...`

// Saju API 호출 (birthDate/birthTime으로 직접 호출)
// ... 기존 API 호출 로직 재사용 (sajuInfo 대신 birthInfo 사용)

// 성공 후 기록 삽입
await supabase.from('anonymous_consult_views')
  .insert({ fingerprint, consult_type: 'saju' })
```

## 10. 전체 플로우 요약

```
[홈] "상담 시작" 클릭
  ├─ 로그인 유저 → navigate (기존 동작, 제한 없음)
  └─ 비로그인 유저
      ├─ hasUsedConsult() === true → LoginBottomSheet
      │   "로그인하면 매일 이용 가능" / "비회원은 1번만 상담 받을 수 있어요"
      └─ hasUsedConsult() === false → navigate

[사주 상담 페이지] "상담 요청하기"
  ├─ 사주 정보 있음 → /saju-consult/loading
  └─ 사주 정보 없음 → FreeBirthInfoInput (mode='consult', 같은 파일 재사용)
      └─ 입력 완료 → sessionStorage 저장 → /saju-consult/loading

[타로 상담 페이지] "상담 요청하기"
  ├─ 비로그인 + hasUsedConsult() → LoginBottomSheet
  └─ 그 외 → /taro-consult/loading

[Loading Pages] Edge Function 호출
  ├─ 로그인 → 기존 로직 (sajuRecordId/userId)
  └─ 비로그인 → birthInfo(사주) / question만(타로) + 서버 fingerprint 체크
      ├─ CONSULT_LIMIT_REACHED → toast + recordConsultUsed() + 홈 이동
      └─ 성공 → recordConsultUsed() + 결과 저장 + 결과 페이지
```

## 12. 검증 방법

1. **비로그인 타로 상담**: 홈 → 타로 상담 시작 → 질문 입력 → 결과 확인 → 재시도 시 LoginBottomSheet
2. **비로그인 사주 상담**: 홈 → 사주 상담 시작 → 질문 입력 → 사주 정보 입력(FreeBirthInfoInput) → 결과 확인
3. **합산 1회 제한**: 타로 사용 후 사주 시도 시 LoginBottomSheet (역방향도 동일)
4. **로그인 유저**: 제한 없이 매일 사용 가능 (기존 동작 유지)
5. **서버 검증**: localStorage 삭제 후 재시도 → Edge Function에서 CONSULT_LIMIT_REACHED 반환
6. **빌드 확인**: `npx vite build` 성공
